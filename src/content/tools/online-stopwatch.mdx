## The Computer Science of Browser Timing: Why `setInterval` Drifts vs `performance.now()`

Many basic online stopwatch websites suffer from severe timing inaccuracies caused by improper JavaScript timer architecture:

### The Flaw of `setInterval` and Event Loop Queuing
In standard JavaScript, `setInterval(callback, 10)` does not guarantee execution every $10$ milliseconds. Because JavaScript runs on a single-threaded event loop, any CPU-intensive task—such as DOM rendering, garbage collection cycles, or background network requests—delays the timer callback. 

Furthermore, modern web browsers (including Google Chrome, Apple Safari, and Mozilla Firefox) aggressively throttle `setInterval` callbacks to once per second ($1,000\text{ms}$) whenever the browser tab is minimized or placed in the background to conserve device battery. If a stopwatch relies on incrementing a counter inside `setInterval`, it will lose minutes of time when backgrounded.

### ZixTool's Drift-Free Monotonic Clock Engine
To guarantee absolute timing accuracy, ZixTool uses the High Resolution Time API (`performance.now()`):

$$\text{Elapsed Duration} = \text{performance.now()} - T_{\text{start}} + T_{\text{accumulated}}$$

`performance.now()` measures monotonic floating-point milliseconds elapsed since the document's navigation start (`timeOrigin`). Monotonic timestamps possess critical engineering properties:
- **Immune to System Clock Adjustments:** If your computer updates its system clock via Network Time Protocol (NTP) or transitions across Daylight Saving Time, `performance.now()` continues advancing strictly forward at the hardware CPU clock rate.
- **Microsecond Precision:** Provides sub-millisecond accuracy ($\pm 5\text{ microseconds}$ after anti-Spectre mitigations).
- **Background Tab Resilience:** Even if a browser tab is throttled to sleep for 30 minutes, querying `performance.now()` upon waking immediately calculates the exact mathematically correct elapsed duration.

## Split Times vs Lap Times: Understanding the Difference

When timing multi-segment athletic events, industrial manufacturing cycles, or speedcubing routines, understanding the distinction between split times and lap times is essential:

- **Cumulative Split Time:** The total elapsed time measured from the initial start gun $(T_0)$ to the moment a specific checkpoint is reached:
  $$\text{Split}_k = T_k - T_0$$
- **Discrete Lap Time:** The isolated duration elapsed strictly between the previous checkpoint $(T_{k-1})$ and the current checkpoint $(T_k)$:
  $$\text{Lap}_k = T_k - T_{k-1}$$

ZixTool automatically computes both values for every recorded checkpoint, highlighting your **fastest lap in green**, **slowest lap in red**, and calculating running averages across the entire sequence.
