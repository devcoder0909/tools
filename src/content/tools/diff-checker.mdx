## The Computer Science of Diffing: Myers' $O(ND)$ Algorithm & LCS

Diffing algorithms solve the fundamental mathematical problem of finding the **Longest Common Subsequence (LCS)** and the **Shortest Edit Script (SES)** between two text sequences:

### Eugene Myers' Difference Algorithm
First published in 1986, the Myers algorithm models the comparison between two sequences $A$ (length $N$) and $B$ (length $M$) as an edit graph traversal:
- The horizontal axis represents tokens in sequence $A$.
- The vertical axis represents tokens in sequence $B$.
- A horizontal edge represents a deletion from $A$.
- A vertical edge represents an insertion into $B$.
- A diagonal edge represents an identical token match that incurs zero edit cost.

The algorithm discovers the shortest path from coordinate $(0,0)$ to $(N,M)$ with time complexity $O(ND)$, where $D$ represents the total number of differences (deletions and insertions). When two documents are nearly identical, $D$ is small, enabling instantaneous comparison even across thousands of lines of text.

### Granularity Modes: Line vs Word vs Character Diffing
Standard command-line tools like GNU `diff` operate at the line level. However, modern document review demands multi-tiered granularity:
- **Line-Level Diffing:** Identifies entire blocks of text that were added, removed, or relocated.
- **Word-Level Diffing:** Isolates specific word substitutions within an otherwise identical paragraph—ideal for editorial proofreading and contract redlining.
- **Character-Level / Intra-Word Diffing:** Highlights exact typographical modifications, altered numbers, or changed punctuation marks (such as changing `$10,000` to `$10,500`), ensuring that no subtle alteration escapes notice.

## Handling Whitespace, Line Endings, and Case Sensitivity

Subtle invisible characters can trigger false positives in basic comparison tools. ZixTool includes advanced normalization filters:

- **Line Ending Normalization (CRLF vs LF):** Windows systems terminate lines with Carriage Return + Line Feed (`\r\n`), whereas Unix, Linux, and macOS systems use Line Feed (`\n`). Transferring files between operating systems often marks every single line as modified. ZixTool automatically normalizes line endings prior to computing the diff.
- **Ignore Whitespace Option:** Strips leading indentation, trailing spaces, and multiple tab characters, allowing you to focus purely on semantic text changes rather than cosmetic formatting tweaks.
- **Case Sensitivity Controls:** Toggle between strict case matching and case-insensitive comparison to spot substantive text modifications without being distracted by capitalization changes.
