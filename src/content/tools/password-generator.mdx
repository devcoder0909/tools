## Shannon Entropy & The Information Theory of Password Strength

Password strength is not determined by how "clever" a phrase looks to a human, but by its mathematical **Shannon entropy**, measured in **bits ($E$)**. Information-theoretic entropy quantifies the number of guesses an adversary must make to brute-force a password under worst-case assumptions.

The fundamental entropy equation is:

$$E = L \cdot \log_2(N)$$

Where:
- **$E$ (Entropy in Bits):** The total cryptographic entropy score. Every additional bit of entropy **doubles** the computational effort required to guess the password ($2^E$ total combinations).
- **$L$ (Password Length):** The total number of characters in the string.
- **$N$ (Character Pool Size):** The size of the alphabet from which characters are randomly sampled:
  - Lowercase letters only (`a-z`): $N = 26 \implies \log_2(26) \approx 4.70 \text{ bits/char}$
  - Alphanumeric mixed case (`a-z, A-Z, 0-9`): $N = 62 \implies \log_2(62) \approx 5.95 \text{ bits/char}$
  - Full ASCII keyboard with symbols (`a-z, A-Z, 0-9, !@#$%^&*`): $N = 95 \implies \log_2(95) \approx 6.57 \text{ bits/char}$

### Mathematical Example: 8 Characters vs. 16 Characters

- **8-character password with full symbols:**
  $$E = 8 \times \log_2(95) \approx 8 \times 6.5698 = \mathbf{52.56 \text{ bits}}$$
  Total combinations: $95^8 \approx 6.63 \times 10^{15}$. A modern 8× NVIDIA RTX 4090 GPU cluster hashing NTLM at 300 billion guesses/second can exhaust this search space in **under 6 hours**!

- **16-character password with full symbols:**
  $$E = 16 \times \log_2(95) \approx 16 \times 6.5698 = \mathbf{105.12 \text{ bits}}$$
  Total combinations: $95^{16} \approx 4.40 \times 10^{31}$. At 300 billion guesses per second, cracking this password requires **4.65 sextillion seconds** (over **1.47 billion years**), rendering brute-force attacks mathematically impossible.

## Modern Security Standards: The NIST SP 800-63B Guidelines

In past decades, corporate IT policies forced employees to create complex passwords with arbitrary rules (e.g., "must contain at least one uppercase letter, one number, and one punctuation mark, and must be changed every 90 days"). The **National Institute of Standards and Technology (NIST)** officially updated their **Special Publication 800-63B** to ban these legacy practices:

### 1. Length Trumps Complexity Rules
NIST research proved that requiring arbitrary symbols leads users to choose predictable patterns (like capitalizing the first letter and putting `!` or `1` at the end: `Summer2026!`). Raw length ($L \ge 16$) provides exponentially higher entropy than forced symbol patterns.

### 2. End Arbitrary Periodic Password Expirations
Mandatory 90-day password changes cause users to create slightly modified variants of existing passwords (`CompanyPass1!` $\to$ `CompanyPass2!`). NIST explicitly advises organizations **against** forced expiration unless a credential breach is confirmed.

### 3. Screen Against Known Breached Passwords
Instead of enforcing arbitrary composition rules, systems must check newly created passwords against known credential leak databases (such as *Have I Been Pwned*).

## Why `window.crypto` Beats `Math.random()`: Understanding CSPRNG

Many online password generator scripts naively rely on JavaScript's standard `Math.random()` function. This is a severe cryptographic hazard:

### The Flaw of `Math.random()`
In modern browsers, `Math.random()` uses the **Xoroshiro128+** or **xorshift128+** pseudorandom algorithm. These algorithms are optimized for raw graphics speed and game physics, not cryptographic unpredictability. Because their internal state consists of only 128 bits, an attacker observing a few successive generated values can reverse-engineer the internal seed and predict all future outputs with 100% accuracy!

### The Security of `window.crypto.getRandomValues()`
Our generator exclusively employs **Cryptographically Secure Pseudo-Random Number Generators (CSPRNG)** via the browser's native Web Cryptography API (`crypto.getRandomValues()`). CSPRNG draws entropy directly from underlying operating system hardware noise:
- CPU thermal fluctuations
- Interrupt request (IRQ) timing jitter
- Hardware keystroke intervals and mouse coordinate movements

This ensures true cryptographic unpredictability that cannot be reverse-engineered by statistical analysis.

## Passwords vs. Passphrases: The Diceware Methodology

For credentials that must be remembered and typed manually on touchscreens or game consoles, human users often struggle with random character strings like `k8#Fm!9p$Lq2@z7X`.

The alternative is a **Diceware Passphrase**, originally invented by Arnold Reinhold:
- Select 4 to 6 random, unrelated common English words from a vetted dictionary list of 7,776 words ($\log_2(7776) \approx 12.92$ bits per word).
- Example: **`correct-horse-battery-staple`** (Popularized by XKCD #936).
- 5 random words yield $5 \times 12.92 = \mathbf{64.6 \text{ bits of entropy}}$.
- 6 random words yield $6 \times 12.92 = \mathbf{77.5 \text{ bits of entropy}}$.

Passphrases are easy for human memory to retain, fast to type on mobile keyboards, and completely immune to standard dictionary word attacks.

## Developer Code Snippets: Generating Secure Passwords

### 1. Modern JavaScript / TypeScript (Web Crypto API)
```javascript
function generateSecurePassword(length = 16) {
  const charset = "ABCDEFGHIJKLMNOPQRSTUVWXYZabcdefghijklmnopqrstuvwxyz0123456789!@#$%^&*()_+~`|}{[]:;?><,./-=";
  const array = new Uint32Array(length);
  window.crypto.getRandomValues(array);
  
  let password = "";
  for (let i = 0; i < length; i++) {
    password += charset[array[i] % charset.length];
  }
  return password;
}

console.log(generateSecurePassword(20));
```

### 2. Python 3 (`secrets` Module)
```python
import secrets
import string

def generate_secure_password(length=16):
    alphabet = string.ascii_letters + string.digits + "!@#$%^&*()-_=+"
    return ''.join(secrets.choice(alphabet) for _ in range(length))

print("Secure Password:", generate_secure_password(20))
```

### 3. Node.js (`crypto` Module)
```javascript
const crypto = require('crypto');

function generateToken(bytes = 16) {
  return crypto.randomBytes(bytes).toString('hex');
}

console.log("Secure Hex Token:", generateToken(16));
```

### Can Best Converter see or log the passwords I generate?
No. All password generation executes locally using the browser's native `window.crypto` API. Zero network requests are dispatched, meaning your passwords never touch our servers, logs, or databases.

### What is the NIST recommended minimum password length?
NIST SP 800-63B recommends a minimum length of 16 characters combining mixed-case letters, numbers, and symbols to provide sufficient entropy against modern GPU-accelerated brute-force attacks.

### How does password entropy measure security strength?
Shannon entropy measures the exponential unpredictability of a password in bits ($E = L \times \log_2(N)$). Passwords with 80+ bits of entropy are considered cryptographically strong and infeasible to brute-force.

### What makes a password vulnerable to dictionary attacks?
Using dictionary words, predictable character substitutions (like `@` for `a` or `0` for `o`), sequential numbers (`12345`), or personal biographical details (birth years, pet names) allows automated cracking tools to guess credentials in fractions of a second.

### How long does it take for a supercomputer to crack a 16-character password?
A 16-character password with full alphanumeric and symbol sets (105 bits of entropy) would take an advanced 8-GPU cracking rig over 1.47 billion years to exhaustively crack.

### Should I include ambiguous characters like O, 0, l, and 1?
If you frequently need to manually read and type your password across mobile screens or physical devices, excluding visually identical characters prevents human typographical errors. For automated password managers, retaining all symbols provides maximum entropy.
