## The Computer Science of URL Percent-Encoding: RFC 3986 Standards

A Uniform Resource Identifier (URI) is constrained by international networking standards to a limited subset of US-ASCII characters. When transmitting text containing spaces, international accents, non-Latin scripts, or reserved syntactic delimiters over HTTP, the characters must be **percent-encoded** according to **IETF RFC 3986**:

### 1. The Percent-Encoding Triplet Mechanism
Every non-allowed byte is converted into a three-character sequence consisting of the percent symbol (`%`) followed by two uppercase hexadecimal digits representing the 8-bit byte value:

$$\text{ASCII Character ' '} (32_{10} = 20_{16}) \implies \mathbf{\%20}$$

$$\text{ASCII Character '&'} (38_{10} = 26_{16}) \implies \mathbf{\%26}$$

### 2. Multi-Byte UTF-8 Percent-Encoding
When dealing with international characters outside the 7-bit ASCII range (such as accented Latin, Cyrillic, Arabic, or Chinese characters), the character is first encoded into its multi-byte UTF-8 binary representation, and each individual byte is percent-encoded sequentially:
- The French character `é` is represented in UTF-8 by two bytes: `0xC3 0xA9` $\implies \mathbf{\%C3\%A9}$
- The German character `ü` is represented by two bytes: `0xC3 0xBC` $\implies \mathbf{\%C3\%BC}$
- The Chinese character `中` is represented by three bytes: `0xE4 0xB8 0xAD` $\implies \mathbf{\%E4\%B8\%AD}$
- The Rocket emoji 🚀 is represented by four bytes: `0xF0 0x9F 0x9A 0x80` $\implies \mathbf{\%F0\%9F\%9A\%80}$

## Reserved vs Unreserved Characters: The RFC 3986 Classification

The RFC 3986 specification strictly categorizes characters into two distinct classes:

### 1. Unreserved Characters (Never Encoded)
Characters that carry no syntactic meaning within a URI structure are unreserved. These characters should never be percent-encoded:
- Uppercase Letters: `A-Z`
- Lowercase Letters: `a-z`
- Decimal Digits: `0-9`
- Special Punctuation: `-` (Hyphen), `_` (Underscore), `.` (Period), and `~` (Tilde)

### 2. Reserved Characters (Syntactic Delimiters)
Characters that serve as structural delimiters within the URI grammar tree:
- **General Delimiters (gen-delims):** `:` (Scheme / port), `/` (Path separator), `?` (Query initiator), `#` (Fragment anchor), `[` and `]` (IPv6 host bounding), `@` (Userinfo delimiter).
- **Sub-Delimiters (sub-delims):** `!` (Negation), `$` (Sub-path), `&` (Query parameter separator), `'` (Quote), `(` and `)` (Grouping), `*` (Wildcard), `+` (Plus / space), `,` (List separator), `;` (Matrix parameter), `=` (Key-value assignment).

If a parameter value contains a reserved character—such as a user searching for `"C++ & Python"`—failing to encode the `&` causes the web server to interpret `& Python` as an entirely separate parameter key rather than part of the search query.

## JavaScript API Differences: `encodeURI()` vs `encodeURIComponent()`

Frontend software engineers frequently trigger subtle routing bugs by selecting the wrong encoding function in JavaScript:

### `encodeURI()` (Full URL Encoding)
Designed to encode a complete, intact URL. It preserves structural delimiters so the browser can navigate properly:
- **Preserves:** `:`, `/`, `?`, `#`, `&`, `=`, `+`, `@`
- **Encodes:** Spaces, quotes, non-ASCII characters, and angle brackets (`<`, `>`).
- *Example:* `encodeURI("https://example.com/search?q=hello world")` $\implies$ `"https://example.com/search?q=hello%20world"`

### `encodeURIComponent()` (Query Parameter Value Encoding)
Designed to encode an individual parameter *value* intended to be inserted inside a query string. It aggressively escapes all structural delimiters:
- **Encodes:** `:`, `/`, `?`, `#`, `&`, `=`, `+`, `@`, and all non-alphanumeric characters.
- *Example:* `encodeURIComponent("https://example.com")` $\implies$ `"https%3A%2F%2Fexample.com"`
- *Critical Use Case:* Mandatory for OAuth redirect URLs, webhook target parameters, and callback endpoints.

## The Double-Encoding Bug & Server-Side Security (SSRF)

Two major software engineering challenges arise from improper percent-encoding:

### The Double-Encoding Bug (`%2520`)
When a string that has already been encoded is passed into an encoder a second time, the literal `%` character (`%25`) is re-encoded. A space (`%20`) transforms into `%2520`. When the server performs a single decode pass, it produces `%20` instead of a space, resulting in broken URLs and failed database lookups.

### Server-Side Request Forgery (SSRF) Prevention
In cloud microservices, unvalidated or improperly decoded URL parameters can be exploited by attackers to bypass internal firewalls. If an attacker inputs an unescaped or double-encoded path (`%2F..%2F..%2Fadmin`), vulnerable backend proxy servers may forward requests to internal cloud metadata services (`http://169.254.169.254/`). Rigorous percent-encoding validation mitigates injection vectors.
