## Order of Operations: PEMDAS / BODMAS Algebraic Precedence

One of the most critical distinctions between cheap pocket calculators and modern digital calculation engines is the evaluation of mathematical order of operations:

### Immediate Execution vs Algebraic Logic
- **Immediate Execution (Standard Pocket Calculator):** Evaluates operations strictly from left to right as keystrokes are entered. Entering `2 + 3 * 4 =` produces:
  $$(2 + 3) \times 4 = 5 \times 4 = \mathbf{20}$$
- **Algebraic Execution (ZixTool & Scientific Standard):** Respects international algebraic precedence (PEMDAS / BODMAS), prioritizing multiplication and division over addition and subtraction:
  $$2 + (3 \times 4) = 2 + 12 = \mathbf{14}$$

### The Universal Hierarchy of Operations
1. **Parentheses / Brackets ($P$ / $B$):** Inner expressions are computed first.
2. **Exponents / Orders ($E$ / $O$):** Powers, exponents, and principal square roots ($\sqrt{x}$).
3. **Multiplication & Division ($M$ / $D$):** Evaluated concurrently from left to right.
4. **Addition & Subtraction ($A$ / $S$):** Evaluated concurrently from left to right.

## IEEE 754 Floating-Point Math: Why Computers Calculate $0.1 + 0.2 \neq 0.3$

In modern computing, numbers are represented in memory according to the **IEEE 754 standard for binary floating-point arithmetic** (64-bit double precision). Because computers store numbers in base-2 (binary) rather than base-10 (decimal), fractions like $0.1$ and $0.2$ cannot be represented with terminating binary digits:

$$0.1_{10} = 0.00011001100110011..._2 \text{ (repeating infinitely)}$$

When a naive JavaScript application evaluates `0.1 + 0.2`, the resulting binary truncation produces:

$$0.1 + 0.2 = 0.30000000000000004$$

In commercial retail, currency accounting, and engineering, these microscopic floating-point rounding errors can cause erroneous ledger discrepancies. ZixTool implements decimal scaling and epsilon normalization (`Number.EPSILON`) to ensure that basic math calculator online results reflect true base-10 arithmetic without decimal precision artifacts.

## Standard Memory Register Functions Explained

For multi-step mathematical workflows—such as tallying invoice line items or summing multiple subtotals—standard desktop calculators feature four dedicated memory registers:

- **$M+$ (Memory Add):** Adds the current display number to the internal stored memory accumulator without erasing the current screen value.
- **$M-$ (Memory Subtract):** Subtracts the current display number from the internal memory register.
- **$MR$ (Memory Recall):** Recalls and displays the running accumulated total stored in memory.
- **$MC$ (Memory Clear):** Resets the internal memory accumulator back to zero.

*Practical Example:* Calculating $(12 \times 5) + (8 \times 15)$:
1. Enter `12 * 5 =` (Display shows `60`). Press `M+` (Memory stores `60`).
2. Enter `8 * 15 =` (Display shows `120`). Press `M+` (Memory stores `60 + 120 = 180`).
3. Press `MR` (Display immediately shows `180`).
