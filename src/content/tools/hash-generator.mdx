## Comparison of Cryptographic Hashing Algorithms

A cryptographic hash function converts arbitrary data into a fixed-size bit string such that even a single character change drastically alters the resulting digest (avalanche effect).

| Algorithm | Digest Length (Bits) | Hex String Length | Security Status | Primary Use Case |
| :--- | :--- | :--- | :--- | :--- |
| **MD5** | 128 bits | 32 characters | Broken (Collision prone) | Quick file checksums, cache keys |
| **SHA-1** | 160 bits | 40 characters | Deprecated | Git commit references, legacy systems |
| **SHA-256** | 256 bits | 64 characters | Highly Secure (Industry standard) | Bitcoin mining, TLS/SSL certificates, HMAC |
| **SHA-384** | 384 bits | 96 characters | Extremely Secure | High-assurance government cryptography |
| **SHA-512** | 512 bits | 128 characters | Extremely Secure | Large-block message integrity, password hashing |

## Common Applications for Hash Digests

Cryptographic checksums are foundational across modern computing and software engineering:

- **File Integrity Verification:** Compare downloaded software packages (`.iso`, `.exe`, `.tar.gz`) against published vendor SHA-256 checksums to verify zero transmission corruption or tampering.
- **Digital Signatures & TLS:** Secure web certificates, Git commits, and code signing workflows rely on SHA-2 family digests to validate author authenticity.
- **Database Caching Keys:** Generate deterministic, short 64-character lookup keys for massive SQL queries or REST API response bodies in Redis caching clusters.

Your input text and computed hashes are processed entirely client-side using native browser `crypto.subtle.digest()`. Sensitive credentials and passphrases are never transmitted over the network.
