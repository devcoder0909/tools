## The Internal Architecture of PDF Page Orientation: The /Rotate Matrix

In an ISO 32000 compliant PDF document, page orientation is not stored by physically reordering raster pixels or rotating content streams. Instead, each page is governed by an indirect page object dictionary containing a specific structural entry: the `/Rotate` key.

Under the PDF specification, the value of `/Rotate` must be an integer multiple of 90 degrees (specifically 0, 90, 180, or 270) representing clockwise rotation relative to the default orientation. When desktop publishing software or high-speed scanner feeders inadvertently capture a page upside-down or sideways, the internal coordinate matrix (`/MediaBox` and `/CropBox`) becomes misaligned with the intended visual presentation.

ZixTool modifies these internal page dictionaries directly inside your browser's WebAssembly memory heap. Rather than rasterizing your document into blurry bitmap images (which destroys text searchability and balloons file sizes), our engine updates the `/Rotate` integers and recalculates viewport bounding boxes losslessly. The resulting PDF maintains 100% vector typography, searchable OCR text layers, and crystal-clear digital signatures.
