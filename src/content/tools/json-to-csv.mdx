## How Hierarchical JSON Maps to 2D Spreadsheet Tables

While converting flat JSON objects is straightforward, modern web APIs and document databases frequently produce nested objects and array collections. Understanding how the browser parser converts these structures ensures predictable results:

### 1. Top-Level Schema Discovery Across Jagged Records
In flexible document collections, records rarely share an identical set of keys. For example, one record might include a `discount` field while another omits it. ZixTool discovers all unique top-level keys across all objects in the input array to construct the complete header row. If a specific record lacks a property, that cell remains empty, maintaining aligned columns across all rows.

### 2. Handling Nested Child Objects and Arrays
When a record contains nested child objects or arrays:
```json
{
  "id": 101,
  "name": "Sarah Connor",
  "contact": { "city": "Los Angeles", "country": "USA" }
}
```
The browser serializer preserves the nested structure by encoding it into cell text (`"{\"city\":\"Los Angeles\",\"country\":\"USA\"}"`). If your database or spreadsheet requires separate scalar columns (such as `contact_city`), flatten the nested properties prior to export. See our [JSON to CSV data checklist](/guides/json-to-csv-data-checklist/) for practical strategies.

### 3. Escaping Delimiters and Quotes
When string values contain commas, quotation marks, or newline characters, the converter wraps the field in double quotes and doubles any internal quote characters according to RFC 4180 conventions.

## SQL Database Bulk Ingestion: PostgreSQL `COPY` Performance

For backend software engineers and database administrators, converting massive JSON API responses to CSV provides dramatic database performance gains. Inserting $500,000$ JSON records via individual SQL `INSERT` statements requires extensive transaction overhead and can take minutes or hours to complete.

In contrast, converting the payload to CSV and executing a native PostgreSQL bulk loader:
```sql
\copy customer_orders FROM 'orders.csv' WITH (FORMAT csv, HEADER true);
```
streams the binary data directly into the database engine, completing the ingestion of hundreds of thousands of records in mere seconds.
