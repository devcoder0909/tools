## CSV Parsing Mechanics & Practical Delimiter Handling

While comma-separated values appear simple on the surface, real-world spreadsheets require careful attention to delimiters and formatting:

### 1. Delimiter Autodetection
The browser converter automatically identifies common column separators, including standard commas (`,`), European semicolons (`;`), and tab stops (`\t`).

### 2. Line Structure and Quoted Fields
The tool splits rows by line breaks and strips outer quotation marks from header and cell tokens. Because each row is evaluated per line, ensure your source export does not contain unescaped multi-line text blocks within a single cell.

### 3. Data Type Inference: Strings vs Native JSON Primitives
In raw CSV files, all data is stored without explicit type metadata. ZixTool provides optional type coercion:
- **Numbers:** Numeric text like `"42"` or `"199.95"` is converted to native JSON numbers. If large numeric IDs (such as credit card or account numbers) must not undergo precision rounding, retain them as string values.
- **Booleans:** Case-insensitive tokens like `"true"` and `"false"` parse to native booleans.
- **Empty Cells:** Unpopulated cells map to empty strings to maintain consistent object keys.

In raw CSV files, all data is stored without explicit type metadata; every cell is technically a sequence of text characters. When converting to JSON, raw string representation often degrades API performance. ZixTool features intelligent automatic type coercion:

- **Integer & Float Numbers:** Strings like `"42"` or `"199.95"` are converted to native JSON numeric primitives (`42`, `199.95`) rather than stored as text strings (`"42"`).
- **Boolean Values:** Case-insensitive strings like `"true"`, `"false"`, `"TRUE"`, or `"FALSE"` are parsed directly into native JavaScript booleans (`true`, `false`).
- **Null and Empty States:** Unpopulated cells (`,,`) can be configured to map to `null`, an empty string `""`, or omitted from the object payload entirely.
- **Scientific Notation:** Numbers formatted like `"1.5e4"` are evaluated to their numerical value ($15,000$).

| Metric / Property | CSV (Comma-Separated Values) | JSON (JavaScript Object Notation) |

| **Human Readability** | Easy to open and edit in Excel / Google Sheets | Ideal for developers and code editors |

## Structured Output Options: Array of Objects vs Array of Arrays

Depending on your target API or software architecture, ZixTool supports flexible JSON serialization modes:

### 1. Array of Key-Value Objects (Standard Mode)
The first row of the CSV is interpreted as dictionary keys for each subsequent object:
```json
[
  { "id": 1, "product": "Mechanical Keyboard", "price": 129.99, "inStock": true },
  { "id": 2, "product": "Wireless Mouse", "price": 59.50, "inStock": false }
]
```
*Best Used For:* REST API payloads, frontend component props, and MongoDB collection imports.

### 2. Array of Arrays (Compact 2D Matrix)
Omits repeated property keys, storing data as a compact array of rows:
```json
[
  ["id", "product", "price", "inStock"],
  [1, "Mechanical Keyboard", 129.99, true],
  [2, "Wireless Mouse", 59.50, false]
]
```
*Best Used For:* High-volume data transmission where network bandwidth and payload size must be minimized.
