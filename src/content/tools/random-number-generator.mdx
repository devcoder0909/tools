## The Computer Science of Randomness: PRNG vs CSPRNG vs Modulo Bias

Understanding the difference between basic pseudo-randomness and cryptographic entropy is essential when selecting winners, running scientific simulations, or conducting research:

### 1. Pseudo-Random Number Generators (PRNG) & `Math.random()`
Most standard web utilities utilize basic JavaScript `Math.random()`. In modern V8 engines (Chrome and Node.js), `Math.random()` implements the **xorshift128+** algorithm. While computationally fast, standard PRNGs possess major limitations:
- **Deterministic Periodicity:** If an observer captures a sequence of consecutive outputs, the internal mathematical state can be reverse-engineered, allowing future "random" numbers to be predicted with $100\%$ certainty.
- **Unsuitable for Financial Contests:** Never use basic `Math.random()` for cash raffles, cryptographic token generation, or security-sensitive lotteries.

### 2. Cryptographically Secure PRNG (CSPRNG) via Web Crypto API
ZixTool leverages the native browser Web Cryptography API (`window.crypto.getRandomValues()`):

$$\text{Entropy Source} \to \text{Hardware Ring Oscillator / CPU RDRAND} \to \text{Kernel Pool} \to \text{Browser CSPRNG}$$

The Web Crypto API harvests physical entropy from the underlying operating system kernel (such as `/dev/urandom` on Linux/macOS and Windows CNG `BCryptGenRandom`). Sources of environmental entropy include CPU thermal fluctuations, hardware timing jitter, and hardware random number generators (TRNG). The output satisfies **NIST SP 800-90A** statistical randomness benchmarks.

### 3. Eliminating Modulo Bias via Rejection Sampling
A widespread flaw in poorly coded number generators is **modulo bias**. When mapping a 32-bit unsigned integer ($0$ to $2^{32}-1$) to an arbitrary range $[0, R-1]$ using basic modulo arithmetic:

$$\text{Biased Number} = \text{Uint32} \pmod R$$

If $2^{32}$ ($4,294,967,296$) is not evenly divisible by $R$, smaller numbers have a slightly higher probability of selection than larger numbers, introducing subtle mathematical bias. ZixTool implements **rejection sampling**: any random integers falling within the fractional remainder zone are discarded and re-drawn, guaranteeing that every integer in your target range has an identical, mathematically uniform probability:

$$P(X = k) = \frac{1}{\text{Max} - \text{Min} + 1}$$

## Generating Unique Non-Repeating Numbers: The Fisher-Yates Shuffle

When drawing multiple unique numbers (such as picking 5 distinct winners from a pool of 100 contestants), naive algorithms generate numbers and loop repeatedly until a non-duplicate is found. As the number of drawn values approaches the total pool size, this approach degrades into severe performance lag.

ZixTool utilizes the **Fisher-Yates (Knuth) modern shuffle algorithm**, operating in linear $O(n)$ time complexity:

```
For i from n - 1 down to 1 do:
    j = random integer such that 0 <= j <= i
    swap array[i] and array[j]
```

This guarantees an unbiased permutation where every possible combination of winners has equal mathematical likelihood, executing in sub-millisecond time.
